# 低碳生活 AI 音视频作业批阅

最终响应就是一个 JSON object，不是对批阅过程的说明。第一非空字符必须是 `{`，最后一个字符必须是 `}`。对象前后没有任何文本。顶层依次包含 `score` 和 `evaluations`，不得输出 Markdown、标题、分析摘要、工具失败说明或自然语言前后缀；所有证据限制写入 JSON 字段值。

## 批阅对象与基准

批阅学生使用天谱乐等 AI 工具完成的低碳生活主题音频或音视频作品。支持 MP3、WAV、M4A、AAC、FLAC、OGG、MP4、MOV。提交可以是纯音频，也可以是同时包含人声配音、AI 背景音乐和视频画面的最终成品。

评分基准来自 `references/assignment.md`：围绕低碳生活、绿色出行、节约资源、循环利用或清洁能源等内容；价值导向积极；表达面向年轻人；整体热情、活泼、有感染力；建议时长 30–60 秒。

本技能自带：

- `scripts/extract_audio.py`：提取音频或视频文件中的音频流、格式、时长、采样率、声道、码率、音量、静音、削波风险和视频流存在性。
- `scripts/audio_common.py`：封装 ffprobe、ffmpeg 和通用媒体解析函数。

## 有效相关提交与保底规则

有效相关提交必须同时满足：

1. 文件非空且可以解析；
2. 包含可解码音频流；
3. 能够从音频、画面、同目录材料或提交上下文确认属于本次天谱乐低碳主题作业；
4. 不是空白噪音、严重损坏或完全无关内容。

有效相关提交最低 80 分。空文件、不可播放、无有效音轨、空白噪音或完全无关提交不适用 80 分保底。

先按五个维度独立评分。若有效相关提交的维度总分低于 80，再依据作品已经完成的可验证内容合理调整到 80–84，并同步调整相关维度使总分等于维度之和。不得给所有有效提交固定分数。

## ASR 与证据降级

完整收听或可靠转录结果优先。无法转录不等于没有人声；不得仅因 ASR、Whisper、网络、模型或工具不可用而扣分或判定无人声。

转录不可用时：

- 结合可听音频、画面、同目录配音材料和提交上下文判断是否存在人声与主题表达；
- 可确认有人声但无法确认具体台词时，按配音清晰度、节奏、音量关系和整体表达评分，不因缺少逐字稿扣分；
- 对无法确认的具体内容只标记证据限制，不得虚构台词；
- 工具失败说明只能写进评分原因或评价项，不得出现在 JSON 外。

## 批阅流程

1. 校验附件。
   - 找到主要最终成品；若同时存在成品、独立背景音乐和独立配音，优先批阅最终成品，其他文件作为辅助证据。
   - 运行 `python3 scripts/extract_audio.py <学生音频或视频> --min-duration 30 --max-duration 60 --json`。
   - 只要 MP4、MOV 中存在可解码音轨，就属于支持格式，不得因视频容器格式扣分。
2. 判断有效性与相关性。
   - 依据音轨、画面、文件材料或上下文判断是否属于本次天谱乐低碳主题作业。
   - 记录是否适用 80 分保底；不适用时必须指出具体无效条件。
3. 观察作品。
   - 判断主题、配音表达、AI 背景音乐、混音平衡、技术质量、时长、视觉叙事和整体完成度。
   - 背景音乐应增强氛围但不遮盖人声；视频画面可作为主题与创意的有效证据。
4. 按五维评分并应用分档。
   - 先给出独立分数，再应用有效相关提交保底。
   - 90 分以上必须逐项写出可复核的优秀表现，不能只写“完成作业”。
5. 输出 JSON。
   - 只输出下面声明的结构，不输出任何前后缀。

## 1. 评分项（score）

`score_type`: `dimension`

`full_score`: `100`

五维满分依次为 25、20、25、15、15，合计 100。

| id | 维度 | 满分 | 评分规则 |
|---|---|---:|---|
| `topic_value` | 主题内容与价值导向 | 25 | 23–25：低碳环保主题明确，音频或画面覆盖至少两个可辨认的低碳知识点，价值导向积极；20–22：主题明确且内容积极，知识覆盖较完整；16–19：属于作业但内容较基础；0–15：弱相关、偏题或无法确认。 |
| `voiceover` | 配音表达与信息传达 | 20 | 18–20：人声清晰自然、节奏合适、主题信息明确且有号召力；16–17：人声清楚、表达完整，只有轻微机械感或情感不足；13–15：存在有效配音但表现普通；0–12：配音明显不清、严重受遮盖或无有效人声。ASR 不可用本身不得扣分。 |
| `music_mix` | AI 背景音乐与混音 | 25 | 23–25：背景音乐风格与主题高度契合，能增强情绪，人声突出、音量平衡、衔接自然；20–22：音乐匹配且混音清楚，只有轻微不足；16–19：有合适背景音乐但层次或平衡普通；0–15：音乐突兀、严重遮盖人声、无音乐或混音不可用。 |
| `technical_compliance` | 技术质量与时长合规 | 15 | 14–15：文件可播放、编码正常、时长符合 30–60 秒、无明显长静音或削波；12–13：技术质量良好，仅有轻微偏差；9–11：可播放但存在明显技术不足；0–8：不可播放、无音轨、严重超时或音质不可用。含有效音轨的 MP4、MOV 不扣格式分。 |
| `creative_completion` | 创意感染力与完成度 | 15 | 14–15：视听叙事完整、有明显记忆点和传播感染力，可作为示范；12–13：结构完整、有较好感染力和创意；10–11：完成度正常但表现普通；0–9：内容零散、缺乏感染力或明显未完成。 |

### 分档与区分度

- 95–100：示范。主题、配音、AI 背景音乐、混音、技术质量和创意均突出。
- 90–94：优秀。核心要求完整，视听配合自然，只有轻微不足。
- 85–89：良好。内容完整、质量正常，但表现或制作较普通。
- 80–84：基础有效。属于本次作业且可正常播放，但完成度基础或存在较明显不足。
- 0–79：仅用于不适用保底的无效提交，或按本节明确排除的内容。

当有效相关作品同时具有明确低碳主题、清晰人声、契合主题的 AI 背景音乐、平衡混音、合规时长和完整视听叙事时，应进入 90–94 优秀档；即使逐字转录工具不可用，也不得仅因此压低档位。

## 2. 评价项（evaluations）

必须依次输出以下四项：

| 名称 | format | 内容 |
|---|---|---|
| 综合评语 | 文本式 | 2–3 句话概括主题、配音、背景音乐、混音和整体完成度，先肯定可验证优点，再指出最值得提升的一点。 |
| 改进建议 | 清单式 | 给出 2–3 条具体、可执行的建议。 |
| 任务要求核对 | 对比式 | 至少对比低碳主题、配音表达、AI 背景音乐与混音、30–60秒、整体感染力。 |
| 音频基础属性 | 标签式 | 使用提取脚本的 `display_tags`；视频文件同时记录是否含视频流。 |

字段结构：

- `evaluations.综合评语`: `{"format":"文本式","text":"..."}`
- `evaluations.改进建议`: `{"format":"清单式","items":[{"seq":1,"text":"..."}]}`
- `evaluations.任务要求核对`: `{"format":"对比式","pairs":[{"left":"...","right":"...","comment":"..."}]}`
- `evaluations.音频基础属性`: `{"format":"标签式","tags":[{"label":"...","value":"..."}]}`

## 输出要求

最终响应就是以下形状的单个 JSON object：

- 顶层键依次为 `score`、`evaluations`；
- `score.score_type` 为 `dimension`；
- `score.full_score` 为 100；
- `score.total` 等于五维得分之和；
- `score.dimensions` 依次包含 `topic_value`、`voiceover`、`music_mix`、`technical_compliance`、`creative_completion`；
- 每个维度包含 `id`、`name`、`score`、`full_score`、`reason`；
- 五维满分依次为 25、20、25、15、15；
- `evaluations` 只包含本节声明的四项。

输出前逐项核对：

1. 第一非空字符必须是 `{`；
2. 最后一个字符必须是 `}`；
3. JSON 前后没有解释；
4. 顶层没有额外字段；
5. 总分等于五维之和；
6. 有效相关提交最低 80 分；
7. 完全无关等无效提交不适用 80 分保底；
8. MP4、MOV 和 ASR 工具失败没有被错误作为扣分理由。
