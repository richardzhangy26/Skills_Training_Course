# 天谱乐音视频作业批阅 Skill 优化设计

**日期：** 2026-07-15

**目标 Skill：** `.qoder/skills/grade-low-carbon-ai-voiceover`

**验收样本：** `南京职业技术学校-AI音视频作业/模块二5.3 使用AI工具天谱乐生成背景音乐/作业.mp4`

## 背景与问题

现有 skill 以“低碳生活 AI 配音音频”为主要批阅对象，只把 MP3、WAV、M4A、AAC、FLAC、OGG 列为支持格式。实际学生作业是包含视频画面、人声配音和 AI 背景音乐的 MP4 成品。

当前版本的基线 QoderCLI 测试得到 83 分。客观提取脚本可以从 MP4 中读取 56.94 秒 AAC 立体声音轨，但会把 `.mp4` 标记为不支持格式。QoderCLI 尝试使用 Whisper 转录时因模型下载失败而无法确认配音内容，随后按证据不足保守扣分。原始 stdout 还包含 JSON 前置说明，不能直接由 `json.loads` 解析。

上一轮 36 分结果来自把纯背景音乐 `跃动晨光.mp3` 作为附件，并非 `作业.mp4` 的音轨提取失败。

## 目标

1. 让现有 skill 正确批阅包含视频、人声和 AI 背景音乐的天谱乐作业成品。
2. 对可播放、非空且可以确认属于本次天谱乐作业的有效提交实行 80 分保底。
3. 保留优秀作业的区分度，使主题、配音、背景音乐、混音、技术质量和创意均表现良好的作品进入 90 分以上。
4. 让 QoderCLI 原始 stdout 严格满足 JSON-only 约束。
5. 用指定 `作业.mp4` 进行真实 QoderCLI 验收，目标总分不低于 90 分。

## 非目标

- 不修改学生提交文件。
- 不把空文件、不可播放文件、无有效音轨或完全无关内容纳入 80 分保底。
- 不为了单个样本写死文件名、固定分数或不可复用的答案。
- 不引入必须联网下载的语音识别模型作为评分前提。

## 方案

采用“修改现有 skill 与媒体提取脚本”的方案，不创建新的平行 skill。

### 1. 批阅对象与有效性

skill 的批阅对象扩展为低碳主题的 AI 音频或音视频成品，允许学生提交纯音频，也允许提交包含画面、人声配音和 AI 背景音乐的 MP4、MOV 等视频。

满足以下条件时视为有效相关提交：

- 文件非空且可以解析；
- 存在可解码音频流；
- 能从音频、画面、同目录材料或提交上下文确认属于本次天谱乐低碳主题作业；
- 不是空白噪音、严重损坏或完全无关内容。

### 2. 媒体提取

扩展媒体格式白名单，至少加入 `.mp4` 和 `.mov`。提取逻辑继续以“是否存在可解码音频流”为核心判断，而不是只依据扩展名。

对视频文件输出视频流存在性、音频编码、时长、采样率、声道、码率、音量、静音和削波等客观信息。只要视频内音轨可正常解析，就不得因提交为视频格式扣分。

### 3. 人声与证据降级

完整收听或可用转录结果优先用于判断配音内容。若 ASR、Whisper 或外部模型不可用：

- 不得把“无法转录”写成“没有人声”；
- 不得仅因转录工具失败而压低有效提交至 80 分以下；
- 应结合可听音频、画面、文件结构、同目录配音材料和上下文进行判断；
- 对无法确认的细节标记证据限制，不虚构具体台词。

### 4. 评分结构与区分度

总分保持 100 分和五维结构，同时把背景音乐及混音质量纳入明确评分依据：

| 维度 | 满分 | 核心判断 |
|---|---:|---|
| 主题内容与价值导向 | 25 | 是否围绕低碳环保展开，内容和画面是否积极、相关 |
| 配音表达与信息传达 | 20 | 是否存在清晰人声，表达是否自然、有号召力、能传达主题 |
| AI 背景音乐与混音 | 25 | 音乐是否契合主题，是否与人声平衡，衔接是否自然 |
| 技术质量与时长合规 | 15 | 可播放性、时长、音量、静音、削波、编码和导出质量 |
| 创意感染力与完成度 | 15 | 视听叙事、创意、传播感染力和成品完整度 |

分档规则：

- 95–100：主题、配音、背景音乐、混音、技术质量和创意均突出，可作为示范。
- 90–94：整体优秀，核心要求完整，只有轻微不足。
- 85–89：完成良好，内容完整但表现或制作较普通。
- 80–84：属于本次作业且可正常播放，但完成度基础或存在较明显不足。
- 0–79：仅用于无效、不可播放、无有效音轨、空白噪音或完全无关提交。

评分时先独立给出五维得分，再应用有效相关提交的 80 分保底。不得给所有有效提交统一分数；90 分以上必须有可复核的优秀表现依据。

### 5. 输出契约

最终输出仍保持顶层只有 `score` 和 `evaluations`。第一非空字符必须是 `{`，最后一个字符必须是 `}`，不得输出分析说明、Markdown、标题或自然语言前后缀。

五个维度使用稳定标识，并保证维度之和等于 `score.total`。四个评价项继续采用文本式、清单式、对比式和标签式格式。证据不足只写入字段值和评分原因，不得在 JSON 外解释。

## 测试与验收

### RED 基线

已使用当前 skill 对 `作业.mp4` 执行 QoderCLI：

- 总分：83；
- MP4 被标记为不支持格式；
- Whisper 模型不可用后对人声和年轻化表达保守扣分；
- stdout 含 JSON 前置说明，严格 `json.loads` 失败。

### GREEN 验收

修改后使用相同模型、相同附件和相同 JSON-only 提示执行：

```bash
qodercli -m qmodel_latest --yolo -p \
  --cwd /Users/zhangyichi/工作/能力训练/homework_review \
  --attachment "/Users/zhangyichi/工作/能力训练/homework_review/南京职业技术学校-AI音视频作业/模块二5.3 使用AI工具天谱乐生成背景音乐/作业.mp4" \
  "使用 $grade-low-carbon-ai-voiceover 批阅附件。只输出一个有效 JSON 对象，顶层只有 score 和 evaluations；不要解释、不要 Markdown、不要代码块。"
```

验收必须同时满足：

1. QoderCLI 退出码为 0；
2. 原始 stdout 可直接由 `json.loads` 解析；
3. 顶层只有 `score` 和 `evaluations`；
4. 总分不低于 90；
5. 五维得分不超过各自满分，且得分之和等于总分；
6. 评价项名称和格式符合 skill 声明；
7. 评分理由能确认视频含有效音轨，并且不因 MP4 格式或 ASR 不可用本身扣分；
8. 高分理由来自作品的可复核表现，而不是文件名、固定样本或硬编码分数。

## 循环停止条件

每轮只做一项能够解释当前失败的最小 skill 或脚本修改，然后用同一附件重新验收并保存 stdout、stderr 和验证结果。

- 成功：全部验收条件通过。
- 无进展：连续一轮修改没有改善对应失败项，停止并报告证据。
- 阻塞：QoderCLI、模型或附件处理出现无法通过 skill 修改解决的外部故障，停止并报告阻塞点。
- 需要确认：修改将改变既定作业范围或评分政策时，暂停请求用户决定。
