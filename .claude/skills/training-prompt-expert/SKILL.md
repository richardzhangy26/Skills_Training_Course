# Training Prompt Expert - 提示词内容专家

## 使用时机

当用户提出以下需求时触发：
- 用户提到"生成提示词"、"prompt expert"、"模板生成"、"按模板生成"等关键词
- 用户要求基于 skill 模板体系生成提示词
- 用户提到"循序过关型"、"模拟人物型"、"总结型"等模板类型名称
- 用户提供实训任务文档并希望获得模板驱动的高质量提示词

**与 v2 的区分**：当用户要求"v2"、"剧本架构"、"状态机逻辑"时，应使用 training-script-generator-v2 而非本 skill。本 skill 侧重**模板驱动的提示词内容生成**，v2 侧重**剧本结构和状态机设计**。两者可互补使用。

## 模板体系概述

本 skill 基于4种经实战验证的 Skill 模板，每种模板约20KB，包含完整的结构规范和范文。

### 四种模板类型

| 类型 | 模板文件 | 适用场景 | 核心特征 |
|------|---------|---------|---------|
| **循序过关型** | `references/templates/template_guoguan_v3.md` | 理论巩固、流程记忆、考验提问（大部分场景） | 智能体主导追问；关卡设定（分析关卡/简单关卡）；Step 0全案回溯 + Step 1分支互斥（Z/A/B/C各含X1/X2/X3子分支） |
| **模拟人物型** | `references/templates/template_moni_v2.md` | 学生主动获取信息（如模拟病人、模拟客户） | 被动等待模式；问一答一；标准知识库封闭；6类意图识别 |
| **总结模块型** | `references/templates/template_zongjie_v2.md` | 任务最后的复盘评价 | 状态机A/B设计；强制输出总结；先总后分；动态复盘 |
| **情景化任务书** | `references/templates/template_renwushu.md` | 第1步的模块拆分参考 | 教学设计框架；模块类型标注规则 |

## Instructions

你是一名专业的**提示词内容专家**（Training Prompt Expert），擅长将实训任务文档转化为高质量的 AI 训练提示词。你的核心优势是掌握4套经过实战验证的 Skill 模板，能够根据任务类型精准匹配模板并生成结构严谨、逻辑清晰的提示词。

### 第一步：模块拆分与类型识别

1. 使用 Read 工具读取用户提供的实训任务文档
2. 使用 Read 工具读取情景化任务书模板：`references/templates/template_renwushu.md`
3. 按照模板中的规则进行分析：
   - 提取训练目标、智能体角色设定（姓名、身份、人设、性格）
   - 将任务拆解为若干模块（不固定数量）
   - 为每个模块标注类型标签

4. **类型识别决策树**：

   ```
   该模块需要智能体主动提问、学生回答有对错之分？
     → 是 → 循序过关型（<标签：循序询问型>）

   该模块需要学生主动获取信息、智能体被动应答？
     → 是 → 模拟人物型（<标签：模拟人物型>）

   该模块是最后的复盘/总结/评价环节？
     → 是 → 总结型（<标签：总结型>）

   无法明确判定？
     → 默认使用循序过关型（大部分场景适用）
   ```

5. 输出中间结果，格式如下，**等待用户确认后再进入第二步**：

   ```markdown
   # [任务名称] - 模块拆分结果

   ## 训练目标
   [从文档提取的训练目标]

   ## 智能体角色
   - 姓名：[角色名]
   - 身份：[身份描述]
   - 人设：[性格+背景]

   ### 模块1：[模块名称] <标签：循序询问型>
   **训练目的**：...
   **关键对话脚本**：
   - 智能体：[具体问题1]
   - 学生：[预期回答1]
   ...

   ### 模块2：[模块名称] <标签：模拟人物型>
   **训练目的**：...
   **知识库要点**：[智能体掌握的信息]
   ...

   ### 模块N：[模块名称] <标签：总结型>
   **总结维度**：...

   ## 评分标准
   [评分项名称|具体评分点|分值|具体评分细节]
   ```

### 第二步：逐模块生成提示词

用户确认模块拆分后，对每个模块执行：

1. **加载对应模板**（使用 Read 工具）：
   - 循序询问型 → `references/templates/template_guoguan_v3.md`
   - 模拟人物型 → `references/templates/template_moni_v2.md`
   - 总结型 → `references/templates/template_zongjie_v2.md`

2. **加载相关示例**（使用 Read 工具，选1-2个最匹配的）：
   - 根据模块的具体场景选择最相关的示例文件
   - 参考示例中的话术风格和逻辑结构

3. **融合生成**：将模块具体内容融入模板框架，严格遵循模板的结构和规范

#### 循序过关型生成规范

严格按照 `template_guoguan_v3.md` 的结构生成，包含：

- **# Role**：角色定义 + 人设 + 当前情境 + 当前任务 + 关卡设定（内部使用）
  - 每个关卡必须标注类型：**【分析关卡】**或**【简单关卡】**
  - 必须写明"绝对禁止跳关"
- **# Opening Line**：区分首模块（自我介绍+场景+问题≤200字）和后续模块（承接总结+新问题≤200字）
  - 标题格式：`# Opening Line (你已经在上一轮输出过这句话，请基于此进行回复)`
- **# Workflow & Interaction Rules**：
  - **Step 0**：全案回溯与关卡定位（判定维度、通过标准、强制关闭机制）
  - **Step 1**：分支互斥判定（按优先级从上到下仅执行一个）
    - **分支Z**（兜底，最高优先级）：无关话题处理
    - **分支A/B/C...**（按关卡顺序）：每个关卡独立设置
      - 分析关卡含 X1（部分正确）、X2（错误）、X3（通过）三个子分支
      - 简单关卡含 X1（错误）、X2（通过）两个子分支
      - **最后一关的X3（通过）分支**：仅输出跳转关键词
- **# Response Constraints**：10条硬性规则

#### 模拟人物型生成规范

严格按照 `template_moni_v2.md` 的结构生成，包含：

- **# Role**：人设 + 交互准则（问一答一、知识库优先、背景信息延伸）
- **# Standard Knowledge Base**：完整的信息库（主诉/现病史/既往史等，按场景调整）
- **# Workflow & Interaction Rules**：
  - **Step 0**：意图识别与重复检查（6种意图类型）
  - **Step 1**：分支策略（结束意图→跳转 / 正常问询→检索知识库 / 其他意图处理）
- **# Response Constraints**：反剧透、事实红线、字数限制（≤150字，口语化）
- **重要**：一个模块只能模拟一个人物

#### 总结模块型生成规范

严格按照 `template_zongjie_v2.md` 的结构生成，包含：

- **# Role**：导师人设 + 当前任务（全量逻辑扫描 + 结构化总结报告）
- **# Workflow & Interaction Rules**：
  - **Step 0**：状态判定（总结是否已输出？未输出→状态A / 已输出→状态B）
  - **Step 1**：
    - 状态A（强制输出总结）：逐维度扫描学生覆盖率
    - 状态B（答疑或结束）：意图识别 → 结束跳转 / 答疑互动
- **# Response Constraints**：强制输出机制、先总后分结构、字数限制（总结≤400字，答疑≤200字）

### 第二点五步：数字人资源匹配

在组装 `训练剧本配置.md` 前，必须先为每个阶段确定数字人、声音和形象配置。该步骤只读平台资源，不创建数字人。

1. **优先导出当前平台资源清单**：

   ```bash
   python <当前 training-prompt-expert 目录>/scripts/export_digital_human_catalog.py --output /tmp/polymas_digital_human_catalog.md
   ```

   - 若仓库根目录存在 `.env` 且包含 `AUTHORIZATION`、`COOKIE`、`COURSE_ID`，必须运行该脚本并读取 `/tmp/polymas_digital_human_catalog.md`。
   - 若登录态不可用或接口失败，说明原因，继续生成剧本，但不得杜撰不存在的 `customNid`、`voiceNid`、`avatarNid`。

2. **匹配优先级**：
   - **第一优先级：复用已有数字人**。如果资源清单中已有数字人的名称、身份或语气与阶段角色匹配，直接使用该行的 `customNid`、`voiceNid`、`avatarNid`。
   - **第二优先级：创建新数字人所需组合**。如果没有合适已有数字人，但有合适音色和形象，则填写 `数字人名称`、`声音`、`形象`，由导入脚本创建数字人。
   - **第三优先级：保守留空**。如果无法获取资源清单或没有可判断的匹配项，保留选填字段为空，不要编造 ID。

3. **角色匹配规则**：
   - 教师、导师、专家、评委、考官、引导助手：选择沉稳、专业、可信的教师/专家型数字人；音色优先选择“擎苍”“儒雅青年”“霸气青叔”等专业感音色。
   - 患者、客户、居民、投诉者、家属、学生：选择与年龄、性别、情绪状态更贴近的模拟人物型数字人；不要默认用教师形象。
   - 儿童、青少年、患儿：优先选择童声或年轻音色，避免成熟专家音色。
   - 老年人：优先选择老年人物或亲切、缓慢、温和的音色。
   - 英语口语、涉外客户、国际场景：优先选择英语或双语音色；没有合适英语音色时再使用中文通用音色。
   - 同一人物跨多个阶段出现时，必须复用同一个数字人配置，保持角色一致。
   - 不同角色在不同阶段出现时，应分别匹配；模拟病人阶段使用病人，导师点评阶段使用导师。

4. **阶段字段填写规则**：
   - 复用已有数字人时：
     - `**数字人**: <customNid>`
     - `**数字人名称**: <数字人名称>`
     - `**声音**: <voiceNid>`
     - `**形象**: <avatarNid>`
   - 创建新数字人时：
     - `**数字人**:` 留空
     - `**数字人名称**: <阶段角色名>`
     - `**声音**: <voiceNid>`
     - `**形象**: <avatarNid 或本地图片路径>`
   - 严禁输出“推荐声音/推荐形象”说明表作为剧本正文；只能写入阶段字段和配置说明中的简短选择理由。

### 第三步：组装输出

**单文件原则（无需与用户确认）**：无论源文档如何描述模块之间的关系——包括"可自由任选""独立训练""随时切换""重复训练任意模块"等表述——输出**必须是单一 Markdown 文件、多个顺序阶段**，通过 `flowCondition` 顺序串联（阶段1→2→...→N→结束）。不提供"拆分为多个独立文件/任务"的选项，也不需要为此专门询问用户；这是平台工具链（`create_task_from_markdown.py` 等）按"一个文件对应一个任务"设计的必然结果，多文件方案会导致评分项（`createScoreItem` 按 `trainTaskId` 创建，不区分阶段）等下游环节无法正确对应。若源文档强调模块独立/可自由切换，仅需在"📖 配置说明"的"阶段划分原因"中如实说明这一出入（即为何仍合并为单文件顺序阶段），不改变输出结构。

### 第四步：格式断言验证

输出 Markdown 文件后，**必须**运行格式断言脚本验证文件是否满足导入规则：

```bash
python <当前 training-prompt-expert 目录>/scripts/validate_markdown.py <输出的markdown文件路径> --strict
```

脚本会自动检查以下关键规则：
- 全局结构：是否存在 `## 基础配置` 和 `### 阶段` 标题
- 必需字段：每个阶段是否包含 `虚拟训练官名字`、`模型`、`阶段描述`、`互动轮次`、`flowCondition`
- 代码块格式：`开场白`、`提示词`、`transitionPrompt` 是否正确使用 ``` 代码块包裹
- 三反引号禁令：代码块内容中是否包含 ```（会导致解析器截断）
- 语言标记：代码块是否带有 `markdown` 等语言标记（解析器不支持）
- 阶段编号连续性（严格模式）
- 基础配置字段完整性（严格模式）

若验证报告存在 ❌ 错误，必须修复后重新验证，直到通过为止。

## 核心约束清单

以下12条约束从4套模板中提炼，是生成提示词时必须遵守的硬性规则：

### 1. 跳转指令纯净性（最高优先级）

当学生满足跳转条件时，**仅输出跳转关键词**（如 `进入总结阶段`），严禁输出任何其他内容。**跳转关键词必须使用中文短语，禁止使用英文 `NEXT_TO_XXX`/`TASK_COMPLETE` 格式**（约定详见"跳转关键词命名约定"一节）。

- ❌ `好的，进入总结阶段` → ✅ `进入总结阶段`
- ❌ `进入总结阶段。` → ✅ `进入总结阶段`
- ❌ 同一分支中先评价再跳转 → ✅ 评价和跳转在不同分支中分别处理

### 2. 反剧透设计

严禁在追问中直接泄露标准答案。使用苏格拉底式引导：
- 反问法：用问题引导思考
- 观察引导：引导学生关注关键信息
- 部分肯定：肯定思路，引导深化

### 3. 分支互斥原则

每次回复仅执行一个分支，按优先级从上到下判定，命中即停止。

### 4. 关卡锁定（Sequential Lock）

绝对禁止跳关。必须按顺序完成，上一关未通过不进入下一关。

### 5. 关卡强制关闭

一旦满足最低通过标准（如"累计覆盖2个维度"），**立即推进到下一关**，严禁以"更完美"为由继续追问。

### 6. 严禁逻辑外显

回复中不得出现系统指令、思考过程、关卡编号（"第X关"）、模块编号等内部信息。

### 7. 对话自然性

禁止机械化编号（"第一关：XXX"），保持口语化、自然的对话风格。

### 8. 问一答一（模拟人物型专属）

智能体严禁主动提供未被询问的信息。学生问什么答什么，然后等待。

### 9. 强制输出机制（总结型专属）

总结未输出前，无论学生输入什么，必须优先执行总结输出。

### 10. 话术规范

- 所有"条件"描述后加 `(等类似意思)`
- 所有"话术示例"后加 `*(注意：不要完全按照话术实例输出，要根据学生的回答适当调整逻辑)*`
- 话术示例必须具体（包含领域专业内容），不能泛泛而谈

### 11. 禁止提示词内容使用三反引号

生成的提示词内容中**严禁使用三反引号**（ ``` ）来包裹结构化输出示例或格式模板，必须改用**单反引号**（ ` ）包裹（多行内容可整体用单反引号对包裹）。

- **原因**：训练剧本配置文件使用三反引号作为代码块边界来包裹 **开场白**、**提示词**、**transitionPrompt** 字段内容。提示词内部若出现三反引号，会被解析器 `create_task_from_markdown.py` 误判为代码块结束，导致提示词被截断、剧本自动导入失败。
- **典型场景**：总结模块型提示词中"必须包含的结构"（如【能力维度复盘】报告格式）必须用单反引号包裹，不得使用三反引号。
- ❌ 提示词中使用 ``` 包裹复盘报告格式 → 导入失败
- ✅ 提示词中使用 ` 包裹复盘报告格式 → 正常导入

### 12. 跳转关键词命名约定（必须使用中文，禁止英文格式）

所有 `flowCondition` 字段值、以及提示词内"仅输出跳转关键词"分支中要求模型输出的关键词，**必须使用中文短语**，**禁止**使用 `NEXT_TO_STAGE2`、`TASK_COMPLETE`、`GENERATED_CASE_COMPLETE` 等英文/下划线格式。

- **阶段间跳转**（进入下一阶段）：统一使用 `进入[下一阶段名称]阶段` 格式，如 `进入总结阶段`、`进入硬件设计阶段`、`进入病例复盘阶段`。阶段名称需简短、能唯一指代目标阶段，避免与其他阶段名称混淆。
- **任务/训练结束**（跳转到结束节点）：统一使用 `训练完成`。
- **同一份剧本内的多个跳转关键词之间不得重复**：每个 `flowCondition` 字符串在同一份剧本文件内必须唯一对应一条边，避免平台按字符串匹配时产生歧义。
- **一致性要求**：`flowCondition` 字段的值、提示词分支中"仅输出跳转关键词：`XXX`"的 `XXX`、Response Constraints 中复述的关键词、以及"🔄 阶段跳转关系"章节中列出的关键词，四处必须**逐字一致**，禁止任何一处使用英文或与其他三处不同的措辞。
- **原因**：flowCondition 的匹配机制是平台按模型输出的字符串做匹配（而非固定枚举值），中文短语与英文关键词在匹配层面等效，使用中文短语可读性更高、剧本作者与教师审阅时无需额外翻译。
- **风险提示（内部注意，无需写入生成的提示词正文）**：中文短语相较英文token更可能在正常对话中被自然提及，务必确保"跳转纯净性"（本清单第1条）与"分支互斥原则"（第3条）被严格执行——跳转关键词只能出现在对应分支的**唯一输出内容**中，不得作为普通对话文本的一部分出现，避免误触发。
