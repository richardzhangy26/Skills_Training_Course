# Training Pro Script Generator

## 目标

把教师提供的任务文档转成可被后续 Python 程序解析的“能力训练 Pro 配置 Markdown”。输出包含全局成员、人物提示词、数字人资源偏好、成员技能和阶段剧本，但不创建、更新、发布平台任务。

## 适用边界

使用本 Skill：

- 多个 AI 全局成员共同参与一张 Pro 卡片
- 每个成员需要独立人物提示词和自定义技能
- 需要为成员选择声音、形象并保留数字人运行时字段
- 配置后续由 Python 脚本导入平台

不要用于普通版能力训练。禁止生成 `conditionRule`、`flowCondition`、`NEXT_TO_*` 或旧版流程边。

## 必读资料

1. `references/example_guoshu_qitiao.md`：内容质量与完整剧本范例。
2. `references/resource_catalog.json`：可直接引用的声音和预置形象候选。
3. `references/platform-resource-resolution.md`：固定资源与运行时 ID 的边界。

## 工作流程

1. 读取教师文档，提取能力目标、真实场景、用户身份、参与人物、任务阶段和专业边界。
2. 规划全局成员。只创建实训中确实需要发言或行动的 AI 人物，不把用户创建为成员。
3. 为每个成员分别生成角色描述、角色提示词、数字人资源配置和技能。
4. 从资源目录按年龄、性别、职业、语言和气质匹配声音与形象。无高置信匹配时使用 `运行时解析`，禁止编造 ID。
5. 将流程拆为阶段卡片，生成五维阶段提示词，并用 `@成员名` 标记发言成员。
6. 写入教师文档同目录，文件名为 `<能力名称>-Pro配置.md`。
7. 运行校验器；修复所有错误后才结束：

```bash
python3 .claude/skills/training-pro-script-generator/scripts/validate_pro_config.py "<输出文件>"
```

## 人物设计规则

### 角色描述与角色提示词分离

- `角色描述`：供平台成员列表展示，说明身份、背景和职责，建议 80-250 字。
- `角色提示词`：供模型稳定扮演，至少 80 字，必须覆盖身份、职责、表达方式和行为边界。
- 人物提示词只负责长期稳定行为，不写具体阶段步骤，不替代阶段剧本。

角色提示词应体现：

1. 这个人是谁，具有什么经验和立场。
2. 在训练中负责提出什么、反馈什么、判断什么。
3. 语言风格、信息密度、称呼方式。
4. 哪些答案不能直接给用户，何时应追问或把任务交还给用户。

### 数字人资源

- 固定声音必须同时输出 `声音名称`、`声音资源ID` 和对应 `声音参数`。
- 固定声音、形象 ID 只能来自 `resource_catalog.json`。
- 无合适候选时，资源 ID 写 `运行时解析`，但选择条件和形象描述仍必须具体。
- `数字人组合ID` 始终写 `运行时解析`；不得复用其他账号或任务中的 `customDigitalHuman`。
- 不输出 `roleNid`、`skillNid` 等平台生成 ID。
- 默认不访问平台。只有用户明确要求实时核验并且环境已有凭证时，才能执行 reference 中的只读查询；绝不调用创建、编辑、删除或发布接口。

## 技能设计规则

每个技能必须服务于该成员的独立职责，不要把成员所有行为塞进一个万能技能。

每个 `<skill_instruction>` 必须包含：

- `### 命令`：唯一、语义明确的 slash 命令
- `### 使用场景`：具体触发时机
- `### 执行规则`：信息边界、推进方式、用户回答后的处理
- `### 输出解释`：回复结构、重点和语气
- `### 示例`：本任务中的真实输入和合规输出

技能描述用于说明触发条件；技能指令用于约束执行过程。两者不能简单重复。

## 阶段剧本规则

每个阶段必须包含：

1. 【阶段触发条件】
2. 【背景设定】
3. 【完整执行流程】
4. 【阶段结束判定】
5. 【行为边界规范】

统一总纲：

> 依据剧本设定统筹实训进程，按既定逻辑调度各角色，有序分配对应任务与履职动作。

成员引用必须写为 `@成员名`，且引用后留空格或标点。用户在阶段提示词中统一称为“用户”，不写 `<role>`、nid、学生姓名或用户具体角色名。

### 阶段结束与后继阶段

- `后继阶段` 是供后续解析器读取的顺序元数据：非最后阶段写下一阶段的精确名称，最后阶段写 `END`。
- 【阶段结束判定】只描述当前卡片何时完成，并写“结束当前卡片，等待平台运行时切换或结束训练”。
- 不得声称模型能够执行平台跳转，不输出跳转命令或旧版条件表达式。

## 输出格式

直接生成下列结构，不输出分析、前言或评价标准：

```markdown
# 能力名称 - 能力训练 Pro 配置

## 全局配置
- **能力名称**: 真实能力名称
- **描述**: 训练目的与场景概述
- **训练方式**: 学生自选
- **默认打开字幕**: 否
- **全程开启摄像头**: 否
- **训练总时长**: 不限时
- **入场音色**: 灿灿
- **封面图描述**: 具体的 16:9 封面画面

## 全局成员配置

### 成员1: 成员昵称
- **角色名称**: 平台显示的角色名称
- **角色描述**: 身份、专业背景和训练职责
- **角色提示词**: 身份、职责、表达方式和行为边界组成的完整提示词
- **模型**: Doubao-Seed-2.0-pro
- **数字人名称**: 与成员昵称一致
- **数字人类型**: NORMAL
- **声音名称**: 资源目录中的名称，或运行时解析
- **声音资源ID**: 资源目录中的 nid，或运行时解析
- **声音参数**: 与声音 ID 对应的 voiceType，或运行时解析
- **声音选择条件**: 语言、性别、年龄、语气和职业气质
- **形象资源ID**: 资源目录中的 nid，或运行时解析
- **形象描述**: 年龄、性别、职业服装、神态和画面风格
- **数字人组合ID**: 运行时解析
- **技能**:
  - 技能名称 | 类型: custom_skill | 描述: 具体触发条件和作用
    <skill_instruction>
    # codemap
    ### 命令
    - /command 操作名称：命令用途
    ### 使用场景
    真实触发时机。
    ### 执行规则
    1. 专业流程和信息边界。
    2. 如何根据用户回答继续推进。
    ### 输出解释
    1. 输出结构、重点和表达要求。
    ### 示例
    用户：本任务中的具体输入。
    模型：遵循规则的具体回复。
    </skill_instruction>

## 训练剧本

### 阶段1: 卡片名称
**卡片描述**: 本阶段目标和场景
**用户扮演角色名称**: 用户在本阶段的完整角色名
**AI 对用户称呼**: 简短自然称呼
**用户扮演角色描述**: 用户身份、职责、已知信息和任务边界
**剧本模型**: Doubao-Seed-2.0-pro
**对话结束策略**: 达成目标后结束
**是否可跳过**: 否
**后继阶段**: 下一阶段精确名称，最后阶段写 END
**背景图描述**: 具体的 16:9 场景画面

**阶段剧本提示词**:
<script_prompt>
依据剧本设定统筹实训进程，按既定逻辑调度各角色，有序分配对应任务与履职动作。

【阶段触发条件】
当前阶段的真实前置条件。

【背景设定】
事件背景、场景环境和基础前提。

【完整执行流程】
步骤1 - 环节名称：
- 参与人员：@成员昵称
- 具体动作：@成员昵称 提出具体任务并等待用户回答。

【阶段结束判定】
可观察、可验证的完成条件。满足后结束当前卡片，等待平台运行时切换或结束训练。

【行为边界规范】
- 允许：本阶段允许的行为。
- 禁止：越界内容和无关互动。
</script_prompt>
```

模板中的说明文字必须替换为教师文档对应的真实内容。唯一允许保留的运行时标记是 `运行时解析`。

## 质量约束

生成后逐项确认：

1. 没有模板占位符、省略号或虚构平台 ID。
2. 每个成员都有不同的角色描述、角色提示词和具体职责。
3. 每个成员的声音、形象与年龄、性别、职业和语气一致。
4. 固定资源 ID 全部存在于资源目录，声音 ID 与声音参数一一对应。
5. `数字人组合ID` 全部为 `运行时解析`。
6. 每个技能具备完整的五段指令结构，示例来自当前任务。
7. 每个阶段具备五维结构、背景图描述和后继阶段元数据。
8. 所有 `@成员名` 都对应已定义成员。
9. 非最后阶段的后继阶段等于下一张卡片名称，最后阶段为 `END`。
10. 不含评价标准、旧版跳转指令、平台写入操作或凭证。

## 不做的事

- 不创建 Python 导入脚本
- 不创建、编辑、删除、发布平台任务
- 不生成评价标准
- 不生成图片，只输出封面、背景和人物形象描述
- 不把账号相关 ID 写死进跨任务剧本
