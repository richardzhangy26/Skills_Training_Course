# 评测架构速查

## 评分维度与权重

| 维度 | 权重 | 满分 | 一票否决 | 说明 |
|---|---|---|---|---|
| 目标达成度 | 0.2 | 20 | **是**（<12 触发） | 知识点/能力是否覆盖教师文档 |
| 流程遵循度 | 0.2 | 20 | — | 环节准入/顺序/流转/准出 |
| 交互体验性 | 0.2 | 20 | — | 人设/自然度/衔接/循环/长度 |
| 幻觉与边界 | 0.2 | 20 | — | 事实/逻辑/承认/围栏/干扰 |
| 教学策略 | 0.2 | 20 | — | 启发/激励/纠错/追问（奖励项） |

**总分 = 5 维度加权和（每项满分 20）= 100 分**

## 子维度清单（21 个）

```
目标达成度（满分 20）
├─ 知识点覆盖率 (10)
└─ 能力覆盖率 (10)

流程遵循度（满分 20）
├─ 环节准入条件 (4)
├─ 环节内部顺序 (4)
├─ 全局环节流转 (4)
├─ 环节准出检查 (4)
└─ 非线性跳转处理 (4)

交互体验性（满分 20）
├─ 人设语言风格 (4)
├─ 表达自然度 (4)
├─ 上下文衔接 (4)
├─ 循环僵局 (4)
└─ 回复长度控制 (4)

幻觉与边界（满分 20）
├─ 事实正确性 (5)
├─ 逻辑自洽性 (5)
├─ 未知承认 (3)
├─ 安全围栏 (3)
└─ 干扰抵抗 (4)

教学策略（满分 20）
├─ 启发式提问频率 (5)
├─ 正向激励机制 (5)
├─ 纠错引导路径 (5)
└─ 深度追问技巧 (5)
```

## 最终等级判定（自上而下）

1. 任意维度触发一票否决 → `一票否决`（pass=False）
2. 总分 ≥ 90 → `优秀`（pass=True）
3. 总分 ≥ 75 → `良好`（pass=True）
4. 总分 ≥ 60 → `合格`（pass=True）
5. 否则 → `不合格`（pass=False）

## 内部调用链

```
scripts/run.py (本 skill)
   ↓ 并发 subprocess
skill_training_evaluation/main.py
   ├─ file_parsers.py      解析教师文档 + 对话日志
   ├─ evaluator.py         外层循环 5 维度 → 内层循环 21 子维度
   │    └─ utils.py:call_llm  每次 HTTP POST 到 LLM 网关
   ├─ prompts.json         21 个子维度提示词模板
   └─ 输出 evaluation.json  结构化报告
```

每次评测 = 21 次 LLM 调用，单次调用 10-60s，整体 5-15 分钟。

## 报告 JSON 字段

```json
{
  "task_id": "...",
  "total_score": 86.0,
  "final_level": "一票否决",     // 优秀/良好/合格/不合格/一票否决
  "pass_criteria_met": false,
  "veto_reasons": ["目标达成度得分10.0分，低于12分阈值"],
  "dimensions": [
    {
      "dimension": "目标达成度",
      "score": 10, "full_score": 20, "weight": 0.2,
      "level": "合格",            // 该维度等级
      "is_veto": true,            // 是否触发一票否决
      "sub_scores": [
        {
          "sub_dimension": "知识点覆盖率",
          "score": 10, "full_score": 10,
          "rating": "优秀",        // 优秀/良好/合格/不足/较差/解析失败
          "judgment_basis": "...",
          "issues": [{ "description": "...", "location": "第1轮", "quote": "...", "severity": "high/medium/low", "impact": "..." }],
          "highlights": [...]
        }
      ]
    }
  ],
  "issues": ["..."],              // 所有 <60% 的子维度汇总
  "suggestions": ["..."],         // 所有 "不足/较差" 的子维度汇总
  "evaluated_at": "ISO 8601"
}
```

## 解析保底（已内置）

当 LLM 返回 JSON 无法解析时：
- `full_score` 取 `config.py` 的子维度原满分（而非 0），避免维度总分被污染
- `rating` 标为 `"解析失败"`
- `judgment_basis` 前缀 `[解析失败，已保留满分占位 N]`

这让单次 LLM 异常不会把整个评测报告判成一票否决。
