# 评价项输出约定

评价项只描述训练表现，不参与总分计算。输出语义字段，不指定A2UI组件类型。

## 5个必评模块

维度评分始终通过根对象 `scoring` 输出。以下四个固定评价项始终通过 `evaluations` 输出且顺序固定。两部分合计为5个必评模块。

### 1. 综合评语

用2至4句话概括任务完成情况、整体能力水平、最突出表现和最主要问题。内容必须与维度得分和学生证据一致。

### 2. 改进建议

输出1至3条可执行建议，优先覆盖主要失分问题。每条包含问题、证据和下一步行动。

### 3. 阶段表现

覆盖本次训练配置或记录中的全部有效阶段，保持原顺序：

```json
{
  "stageId": "入参中的阶段ID",
  "stageName": "入参中的阶段名称",
  "time": "真实时间或阶段顺序标签",
  "stageEvaluation": "该阶段的学生表现评价"
}
```

- `stageId`、`stageName`、`time`、`stageEvaluation` 均为必填字段，且不得为空字符串。
- ID和名称必须原样取自入参，不得根据名称生成ID。
- `time` 优先取入参中的真实阶段开始时间、发生时间或时间范围。若入参没有时间戳，则使用原始阶段序号或按阶段顺序生成展示标签，如“阶段1”“第2阶段”；这只是流程顺序标签，不得伪造成具体日期或时刻。
- 评价只使用该阶段内学生产生的证据，并可结合阶段目标判断完成度。
- 阶段存在但没有学生证据时，明确写“未发现可评价的学生表现证据”。
- 不得把智能体的提问、提示、总结或表扬写成学生表现。

### 阶段表现的A2UI时间线约束

平台将阶段表现识别为 `TIMELINE` 时，输出内容必须包含非空 `items`；每个节点的 `time` 必须是长度至少为1的字符串。语义对应关系如下：

```text
items[i].time = 阶段真实时间 ?? 原始阶段序号 ?? "第" + (i + 1) + "阶段"
items[i].title = stageName
items[i].description = stageEvaluation
```

输出前逐项检查 `items[i].time.trim().length >= 1`。普通版Excel没有时间戳时，不得留空，使用阶段顺序标签。

### 4. 亮点清单

恰好输出4项：

```json
{
  "highlightId": "highlight_1",
  "highlightName": "简短亮点名称",
  "highlightDescription": "与真实训练证据对应的亮点说明"
}
```

- `highlightId` 依次使用 `highlight_1`、`highlight_2`、`highlight_3`、`highlight_4`，同一报告内唯一。
- 亮点按重要程度排序，避免同义重复。
- 学生表现较弱时，可提炼已完成的基础行为、配合度、直接回应、流程遵循等相对可保留点，但不得夸大为不存在的专业能力或成果。
- 证据不足以支持某种能力时，换用有证据的基础行为，不得编造。

## 2个选评模块

测验表现和上传表现不是固定槽位。只有对应测验Skill或上传Skill存在成功、非空且可评价的入参或结果时，才创建对应评价项；条件不满足时，整个评价项必须省略。若选评模块被平台渲染为 `LIST`，`content.cards` 必须至少包含1张真实内容卡片。

这两项不得出现在供技能概览抽取的固定评价项配置表中。它们只能由运行时输入触发，并在完整 `evaluations` 数组中追加；修复轮仍须返回包含全部固定项和动态项的完整数组。

### 选评项1：测验表现

满足以下任一条件，且数据能够确认来自测验Skill的成功调用时才输出：

- `quizzes` 中存在至少一条由测验Skill规范化而来的可读取题目、学生答案和系统判分结果；
- 测验类Skill调用成功，且输出包含题目、学生答案、正确答案、对错或得分。

点评应包含系统总分或正确率、答对与答错情况、题型或知识点表现。客观题沿用实时判分，不重新判定答案。若只有Skill名称、调用记录或空输出，不生成本评价项。

按测验或测验Skill输出以下语义字段：

```json
{
  "quizId": "入参中的测验ID或测验Skill结果ID",
  "quizName": "入参中的测验名称",
  "quizScore": 8,
  "quizFullMark": 10,
  "quizEvaluation": "结合正确率、错题和知识点表现形成的点评"
}
```

- `quizId`、`quizName` 沿用入参值；不得根据名称另造ID。
- `quizScore`、`quizFullMark` 沿用系统实时判分；若系统只提供正确率，则保留正确率，不反推虚构分数。
- 可以汇总单选、多选、判断题表现，但不得改变任何客观题对错结果。
- 若没有有效测验数据，不输出“测验表现”评价项。不得输出空卡片或“本次未触发测验”等占位卡。

### 选评项2：上传表现

满足以下任一条件，且数据能够确认来自上传Skill的成功调用时才输出：

- `uploads` 中存在由上传Skill规范化而来的上传ID、材料名称及可读取正文、解析结果或内容摘要；
- 上传类Skill调用成功，且输出包含可读取的材料内容。

每份材料输出：

```json
{
  "uploadId": "入参中的上传ID",
  "uploadName": "入参中的文件名或材料名称",
  "uploadEvaluation": "针对该材料内容的评价"
}
```

- `uploadId`、`uploadName` 必须沿用入参值。
- 评价材料与当前阶段任务、训练目标和老师维度细则的相关性、完整性、有效性与可用性。
- 不得仅根据文件名推测文件质量。
- 只有上传动作、失败状态或不可读取文件时，不生成本评价项。
- 若没有上传Skill产生的可读取材料，不输出“上传表现”评价项。不得输出空卡片或“本次无上传材料”等占位卡。

## 动态数量与非空规则

最终 `evaluations` 必须按以下顺序输出：4个固定评价项；如有测验Skill有效数据则追加测验表现；如有上传Skill有效材料则追加上传表现。因此合法数量为4、5或6项。加上独立的 `scoring`，完整报告业务模块数量为5、6或7个。

- 两类动态数据都没有：4项。
- 只有测验或只有上传：5项。
- 测验和上传都有：6项。

不存在对应数据时省略整个选评模块，不得输出空数组、`null`、空字符串或状态占位卡。

最终输出前执行：

```text
for evaluation in evaluations:
  if evaluation.type == "LIST":
    assert evaluation.content.cards.length >= 1

assert 4 <= evaluations.length <= 6
```
