# 能力训练通用批阅

## 正式版输入原则

本技能的评分维度不是技能内置配置，而是老师随本次批阅提交的评价标准。输入可以是平台能够读取的任意形式，包括消息正文、结构化数据，以及 PDF、TXT、Word、Excel 等附件，不限制老师评价标准和学生训练记录使用相同文件格式。

1. 放在“作业要求”的正文、结构化数据或附件：老师评价标准，是维度名称、ID、满分和评分细则的唯一来源。
2. 放在“学生提交”的正文、结构化数据或附件：学生能力训练记录，是学生表现证据的唯一来源。

不得按文件格式、文件名或上传顺序猜测用途。先依据消息标签“作业要求/学生提交”确定数据归属，再读取正文、表格或附件解析内容。若平台把多份内容同时交给模型，则以内容语义二次识别：包含“评价标准”“满分”“itemId/dimensionId”“详细要求”的内容为评价标准；包含“聊天记录”“阶段”“学生/用户与智能体发言”的内容为训练记录。

严禁使用演示版、历史任务或技能示例中的任何固定维度。每次批阅都必须重新从本次“作业要求”的评价标准中提取维度。

## 报告模块清单

### 5个必评模块

每次批阅都必须生成，缺少任意一项均视为不完整结果：

1. **维度评分**：位于根对象 `scoring`，按老师本次评价标准逐维度评分。
2. **综合评语**：位于 `evaluations`。
3. **改进建议**：位于 `evaluations`。
4. **阶段表现**：位于 `evaluations`，覆盖全部有效阶段。
5. **亮点清单**：位于 `evaluations`，恰好包含4个有证据的亮点。

### 2个选评模块

仅满足各自触发条件时生成，否则必须完全省略：

6. **测验表现**：检测到测验Skill成功产生的非空、可评价入参或结果时生成。
7. **上传表现**：检测到上传Skill成功产生的非空、可读取材料入参或解析结果时生成。

因此完整报告包含5至7个业务模块；由于维度评分独立存放在 `scoring`，`evaluations` 数组仍为4至6项。

## 最高优先级输出约束

### 首次输出与修复轮协议

- 无论首次批阅还是平台触发的修复轮，必须返回且只返回一个完整、可解析的JSON根对象。
- 根对象必须同时包含完整的 `scoring` 和完整的 `evaluations`；不得只返回出错字段、修复片段、差异补丁或某个子对象。
- 禁止返回解释文字、Markdown代码围栏、道歉、错误原因、“无法解析”“停止评分”等自然语言响应。
- 修复轮必须重新读取本次输入并从头构造完整结果，不得引用“上一轮结果”，不得假设平台会自动合并局部字段。
- 输出前在内存中完成全部检查，再一次性输出JSON。即使需要修正多个问题，也只能输出一次完整结果。
- 除最终JSON外不得产生第二段输出；不得把调试信息、脚本日志或校验结果写入响应。

在开始评分前，先为每条评价标准建立唯一ID映射：

```text
resolvedDimensionId = 标准中的 dimensionId（若存在且非空）
                      否则取标准中的 itemId
```

- 每条评价标准必须至少存在非空的 `dimensionId` 或 `itemId`；不得自行生成ID。
- 若同时存在，以 `dimensionId` 为准，但不得修改其值。
- 每个最终维度对象必须显式输出 `dimensionId: resolvedDimensionId`。
- 每个最终维度对象的 `dimensionName` 必须原样取自本次入参对应评价标准的维度名称。
- `dimensionId`、`dimensionScore`、`scoreReason` 是不可省略的必需字段。
- 严禁输出任何模板占位名称，严禁使用Skill中的示意值覆盖本次入参。
- 在逐项确认所有维度均包含上述三个字段之前，不得输出最终JSON。
- 输出后端或A2UI内容前，先完成评分JSON校验；任何维度缺少 `dimensionId` 均视为无效结果。
- 任何 `LIST` 类型评价项的 `content.cards` 必须至少包含1项；严禁输出 `cards: []`。
- `evaluations` 动态输出4至6项：综合评语、改进建议、阶段表现、亮点清单4项始终存在；测验表现和上传表现分别按对应Skill的有效入参或结果独立追加。无对应数据时完全不输出对应评价项，禁止生成占位卡。
- 不得改用示例维度、历史维度或根据聊天阶段创建维度。平台正常发起批阅时，应以“作业要求”中已经提供的评价标准完成输出，不进入自然语言报错分支。

## 批阅流程

**① 校验两类必需入参**

先根据平台消息标签识别“老师配置的评分标准”和“学生能力训练记录”，再按实际载体读取内容：平台已抽取的PDF、TXT或Word正文直接解析；Excel读取相关工作表；JSON等结构化数据按字段解析。只有两类输入均为可访问的DOCX文件路径时，才可选调用 `scripts/parse_docx_inputs.py`，且第一个参数传老师标准，第二个参数传学生记录。

老师评价标准至少包含一个维度；每个维度必须具有非空的 `dimensionId` 或 `itemId`，以及维度名称、严格大于0的满分值、评价描述和评价项详细要求。学生训练记录必须包含至少一条可识别的学生或智能体发言，或结构化阶段、互动、测验、上传、实操等记录。

按本次实际收到的解析内容完成字段校验。不得自行补充默认维度、默认分值或通用评分细则，不得用聊天记录中的阶段名称代替评分维度。平台正常发起批阅时不得返回字段缺失说明；应继续从“作业要求”的正文、附件解析结果或结构化字段中定位评价标准，并生成完整JSON。

**② 整理学生训练记录**

若输入为普通版能力训练记录Excel且脚本可执行，可调用 `scripts/parse_ability_training_xlsx.py`；其他结构化输入可调用 `scripts/normalize_training_record.py`。脚本不可执行时，直接读取平台提供的表格或结构化内容，不得中断输出。区分“未采集”“未发生”“学生未完成”：未采集的数据不得作为负面证据；训练明确要求但学生未完成的任务，可按照老师配置的相关维度细则扣分。

**③ 按老师配置的每个维度取证评分**

读取 `references/evidence-rules.md`。只把学生实际产生的回答、选择、操作、测验作答和提交内容作为学生表现证据。普通版记录中仅 `role=user` 属于学生证据；`role=assistant` 的提问、提示、纠错、总结和表扬仅作为上下文。

严格按照老师入参中的维度顺序逐项评分。对每个维度：

1. 读取维度名称、满分值、评价描述和评价项详细要求。
2. 从训练记录中查找与该细则直接相关的正向证据、问题证据及未完成的必做行为。
3. 在0至该维度满分范围内给出实际得分。
4. 给出能够定位到学生回答、操作、测验或材料的打分原因。

不得增加、删除、合并、拆分、重命名或重新排序老师配置的维度。每个结果中的 `dimensionId` 必须取对应评价标准的 `dimensionId`；若入参没有该字段，则取 `itemId`。即 `output.dimensionId = input.dimensionId ?? input.itemId`。不得自行生成、改写或使用数组序号代替。

**④ 生成并校验 scoring**

若脚本可执行，可调用 `scripts/calculate_dimension_score.py`，传入老师配置的 `evaluation_standards` 和逐维度判断 `dimension_judgements`；否则直接按照下述同一映射规则构造 `scoring`。

输出前必须满足：

- 输出维度数量与老师配置完全一致。
- 输出 `dimensionId` 与老师配置的 `dimensionId` 或 `itemId` 逐项对应，名称、顺序和满分与老师配置一致。
- `scoreData.fullMark` 等于所有 `dimensionFullMark` 之和。
- `scoring.totalScore`、`scoreData.totalScore` 均等于所有 `dimensionScore` 之和。
- 每个维度满分严格大于0；实际得分允许为0。
- 每个实际得分均位于0至该维度满分之间。

**⑤ 生成4个固定评价项，连同scoring构成5个必评模块**

无论训练是否配置测验、上传或其他互动，始终输出以下四项：

1. 综合评语。
2. 改进建议。
3. 阶段表现：覆盖训练记录中的全部有效阶段，每项包含原始 `stageId`、原始 `stageName`、非空的 `time` 和基于该阶段学生证据生成的 `stageEvaluation`。`time` 优先使用入参中的阶段时间；没有时间戳时使用原始阶段序号或“第N阶段”，绝对不能输出空字符串。
4. 亮点清单：恰好输出4项，每项包含 `highlightId`、`highlightName` 和 `highlightDescription`。亮点必须来自学生真实回答、操作、选择、完成行为或提交内容；表现较弱时可提炼基础完成行为和相对可保留点，但不得捏造能力或成果。

若某阶段存在于训练配置但没有学生表现证据，仍保留该阶段，并在 `stageEvaluation` 中客观说明“未发现可评价的学生表现证据”；不得把智能体发言写成学生表现。

平台可能把阶段表现渲染为 `TIMELINE`。此时 `content.items` 中每一个节点的 `time` 都是必填非空字符串：有真实时间时使用真实时间；没有时间时使用阶段顺序标签，例如“阶段1”或“第2阶段”。不得使用 `"time": ""`。

**⑥ 按条件生成测验表现与上传表现**

- **测验表现**：仅当测验Skill调用成功，且其非空入参或结果中至少存在一条可评价的题目、学生答案、系统判定、得分或正确率时追加。平台若已将该Skill结果规范化到 `quizzes`，按同一条件识别。沿用系统实时分数、正确率和题目判定生成真实点评，不重新判分。没有对应Skill的有效数据时，不创建“测验表现”评价项。
- **上传表现**：仅当上传Skill调用成功，且其非空入参或结果中至少存在一份带上传ID、材料名称及可读取正文、解析结果或内容摘要的材料时追加。平台若已将该Skill结果规范化到 `uploads`，按同一条件识别，并逐份输出材料点评。没有对应Skill的有效材料时，不创建“上传表现”评价项。

只出现测验/上传Skill名称、配置、调用痕迹、空入参、失败状态、空结果、只有文件名或不可读取文件，不视为有效数据。不得因此生成选评模块，也不得输出“本次未触发测验”“本次无上传材料”等占位内容。

构造最终 `evaluations` 数组时，先按固定顺序创建综合评语、改进建议、阶段表现、亮点清单；再依次判断并追加测验表现、上传表现。不得输出 `null`、空数组或空字符串。输出前检查 `4 <= evaluations.length <= 6`，且所有已输出的 `LIST.content.cards.length >= 1`。

**⑦ 输出平台 JSON**

在同一个平台标准JSON中输出 `scoring`、`evaluations`：

- `scoring`：动态总满分、总得分、老师配置的全部维度及逐维度打分原因。
- `evaluations`：前4项固定为综合评语、改进建议、阶段表现、亮点清单；其后根据对应Skill的有效入参或结果依次追加测验表现、上传表现，共4至6项。

首次输出和任何修复轮都仅输出平台标准模板要求的完整合法JSON，不附加解释文字或Markdown代码围栏。输出必须以 `{` 开始、以 `}` 结束，并且根层同时存在 `scoring` 与 `evaluations`。

## 1. 评分项（scoring）

> 必填。评分项结构固定，但维度内容由本次入参动态决定，由平台直接渲染。

`scoringType`：`DIMENSIONS`（维度评分）

`scoreData.fullMark`：老师配置的所有维度满分之和

### 若 scoringType = DIMENSIONS（维度评分，≤10个维度）

**动态维度配置：**

| 字段 | 来源 | 输出要求 |
|---|---|---|
| 维度ID | 入参的 `dimensionId`，没有时取 `itemId` | 必须显式输出为 `dimensionId` |
| 维度名称 | 老师填写的“维度名称” | 原样输出为 `dimensionName`，不得改写 |
| 维度满分 | 老师填写的“满分值” | 原样输出为 `dimensionFullMark`，必须大于0 |
| 评价描述和评分规则 | 老师填写的“评价描述”与“评价项详细要求” | 用于评分，并输出为 `dimensionCriteria` |
| 维度实际得分 | 根据该维度细则和学生证据计算 | 输出为 `dimensionScore` |
| 维度得分原因 | 根据该维度细则和学生证据生成 | 输出为 `scoreReason`，不得为空 |

**满分字段硬约束：**

- `fullMark = sum(dimensions[].dimensionFullMark)`。
- 每个 `dimensions[].dimensionFullMark` 必须与对应入参维度的满分值完全一致且严格大于0。
- 学生缺少相关证据时，只能将实际得分设为0，不能把维度满分设为0。
- 每一个维度对象都必须包含 `dimensionId`、`dimensionScore`、`scoreReason`，三个字段均不得缺失或为 `null`。

**输出字段映射：**

正式输出必须完全根据本次入参逐项构造，不得引用任何预设维度名称、ID、分值或细则：

```text
scoring.scoringType = "DIMENSIONS"
scoring.scoreData.dimensions[i].dimensionId = input.dimensions[i].dimensionId ?? input.dimensions[i].itemId
scoring.scoreData.dimensions[i].dimensionName = input.dimensions[i].维度名称
scoring.scoreData.dimensions[i].dimensionFullMark = input.dimensions[i].满分值
scoring.scoreData.dimensions[i].dimensionCriteria = input.dimensions[i].评价描述 + input.dimensions[i].评价项详细要求
scoring.scoreData.dimensions[i].dimensionScore = 依据第i项细则计算的实际得分
scoring.scoreData.dimensions[i].scoreReason = 依据第i项细则和学生记录形成的得分原因
```

输出数组必须覆盖老师配置的全部维度。若老师配置N个维度，则 `dimensions` 必须恰好输出N项。输出前逐项检查：

```text
dimensions[i].dimensionId == (input.dimensions[i].dimensionId ?? input.dimensions[i].itemId)
dimensions[i].dimensionName == input.dimensions[i].维度名称
dimensions[i].dimensionScore != null
dimensions[i].scoreReason != null && dimensions[i].scoreReason != ""
```

## 2. 评价项（evaluations）

> 必填。评价项用于描述学生训练表现，不参与分数计算，老师可在复审页编辑。详细字段和条件规则见 `references/evaluation-output-contract.md`。

**评价项配置：**

下表只定义4个固定评价项，供平台技能概览建立基础Schema。它们与独立的 `scoring` 合计为5个必评模块。不得在固定配置表中预声明测验表现或上传表现。

| 评价项名称 | 评价项描述 | 评价项生成规则 |
|---|---|---|
| 综合评语 | 对学生本次能力训练整体表现的概括性评价 | 综合本次老师配置的全部评分维度、得分原因和训练证据，用2至4句话概括任务表现、主要优势和核心问题；不得引用不存在的固定维度，不得与实际得分矛盾 |
| 改进建议 | 针对本次训练中最需要改进的问题给出下一次可执行建议 | 输出1至3条建议，每条按照“问题—证据—下一步行动”组织，优先覆盖失分较多或影响任务目标的问题，避免空泛表述 |
| 阶段表现 | 逐阶段说明学生在剧本流程中的实际表现 | 始终输出；每个阶段包含 `stageId`、`stageName`、非空 `time`、`stageEvaluation`，ID和名称必须来自入参；无时间戳时以阶段顺序标签作为 `time` |
| 亮点清单 | 提炼本次训练中值得保留的行为与表现 | 始终且恰好输出4项；每项包含 `highlightId`、`highlightName`、`highlightDescription` |

**动态追加协议（不属于固定评价项配置）：**

- 检测到测验Skill成功产生至少一条包含题目、学生答案及系统判分信息的有效入参或结果时，在4个固定评价项之后追加“测验表现”。规范化后的 `quizzes` 也必须能追溯到该Skill的有效数据。
- 检测到上传Skill成功产生至少一份包含上传ID、材料名称及可读取正文、解析结果或内容摘要的有效入参或结果时，在测验表现之后追加“上传表现”；没有测验但有上传时，直接在4个固定评价项之后追加。规范化后的 `uploads` 也必须满足相同内容条件。
- 条件不满足时不创建对应对象，不输出空对象、空列表或状态占位卡。
- 动态对象必须一次性包含完整名称、描述和内容，不能在修复轮仅返回追加对象。

**输出结果：**

以平台标准要求的JSON格式输出。报告必须始终包含 `scoring` 和4个固定评价项，即5个必评模块；`evaluations` 必须为4至6项，数量由本次对应Skill的有效输入决定。若阶段表现被渲染为 `TIMELINE`，必须保证 `content.items` 存在且每个节点的 `time` 为长度至少1的字符串。任何被渲染为 `LIST` 的已输出评价项都必须保证 `content.cards` 至少有1项；测验或上传无有效数据时省略整个选评模块，不能输出空 `LIST` 或占位卡。
