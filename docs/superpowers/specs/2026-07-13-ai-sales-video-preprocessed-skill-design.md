# AI 销售顾问视频批阅 Skill（前置预处理版）设计

## 目标

新增独立 Skill `grade-ai-sales-consultant-video-preprocessed`。它只使用批阅模块前置数据处理 Skill 已经提取的视频口述内容、PPT 内容和元数据完成评分，不自行拆分音频、不调用 ASR 服务、不读取 API Key。现有 `grade-ai-sales-consultant-video` 保持不变。

## 输入契约

- 视频预处理内容：必填，至少包含顾问口述文本和可区分的片段标识；如果前置处理提供起止时间、说话人和覆盖率，则一并使用。
- PPT 预处理内容：正式评分必填，包含页码或页面标识及对应文字，作为课程上下文和事实核验依据。
- 元数据：`customer_type` 取 `old`、`new` 或 `unknown`；`course_name` 可选；可附前置处理来源、覆盖状态和定位精度。
- 输入可以是结构化字段或已经注入上下文的提取文本；Skill 按语义识别，不绑定某个尚未确定的平台 JSON 字段名。

## 数据流

1. 批阅模块的前置数据处理 Skill 处理视频和 PPT。
2. 本 Skill 检查视频文本是否存在、是否能够覆盖完整汇报，并区分顾问口述与演示媒体内容。
3. 以视频口述为主要评分证据，以 PPT 为事实参考和错失机会来源。
4. 按既有六维标准评分，执行事实扣分与严重红线封顶。
5. 使用结果校验脚本检查总分、维度、评价项格式和元数据。
6. 只输出顶层包含 `score` 和 `evaluations` 的 JSON。

## 证据定位

- 前置处理提供时间范围时，使用该时间范围，不把片段级时间伪装成逐字时间戳。
- 未提供时间范围时，使用“预处理片段编号/段落编号＋近似原话”定位。
- PPT 中存在但视频文本没有出现的内容不能作为正向得分，只能列为错失机会。
- 听写或说话人归属存疑时标记“待人工核验”，不直接扣分。

## 覆盖不足处理

视频口述文本为空、只包含零散摘要或前置处理明确标记覆盖不足时，不调用任何 ASR 作为后备方案。输出“无法批阅（0 分为技术占位）”，并在元数据中说明需要重新执行前置数据处理；不得把技术占位分解释为学员能力表现。

## 评分与输出

沿用现有六维 100 分制、事实扣分档位、R1-R7 红线和 69/59 分封顶规则。评价项仍使用文本式、清单式、对比式、标签式四种格式。

`review_metadata` 至少包含：

- 批阅状态
- 客户类型
- 课程
- 前置处理来源
- 内容覆盖状态
- 证据定位精度
- 严重红线类别
- 总分封顶
- 局限说明

不再包含或要求 ASR 模型、MiMo 凭证来源和音频转写脚本。

## 文件边界

新 Skill 只包含：

- `SKILL.md`
- `agents/openai.yaml`
- `references/rubric.md`
- `references/overpromise_redlines.md`
- `scripts/validate_review_result.py`
- 对应单元测试

不包含 `prepare_sales_evidence.py`、`transcribe_mimo.py`、`mimo_asr.md`、`.env`、API Key 或网络请求代码。

## 验收标准

- 原 ASR 版文件无改动。
- 新 Skill 通过 `quick_validate.py`。
- 结果校验器单元测试通过。
- 静态契约测试确认不存在 MiMo 地址、`MIMO_API_KEY`、具体 ASR 模型名、硬编码密钥和音频转写脚本。
- ZIP 可正常解压，且不包含 `.env`、缓存文件或凭证。
