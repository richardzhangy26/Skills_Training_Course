# AI 销售顾问音频优先批阅优化设计

## 目标

优化现有两个线上 AI 销售顾问批阅 Skill，使同一份参考 PPT 下的优秀、良好、较差三档口述样本稳定进入各自预期区间：优秀 82–95、良好 63–75、较差 20–55。优化不得在 Skill 中写入样本文件名、档位答案、样本专属话术或档位对应分数。

本次采用“音频优先 + 证据门禁”方案。视频画面和 PPT 只提供上下文与事实核验依据，正式得分必须来自能够回溯到真实顾问口述的证据。

## 已确认的基线问题

2026-07-14 的六次平台基线测试显示：

- 带 MiMo 流程的 Skill 得分为优秀 62、良好 63、较差 69，三档排序失效。
- 平台前置预处理 Skill 得分为优秀 66、良好 0、较差 13；良好档被错误判为“无音频轨道”。
- 较差档线上上传文件与本地源文件 SHA-256 一致，排除传错文件。
- 三条源视频都包含完整 AAC 音轨；媒体容器本身不是“无音频”。
- 带 MiMo 流程的线上报告只回显“视频音轨转写”或“多模态听写”，没有证实调用 `mimo-v2.5-asr`。
- 平台前置处理在三条同编码视频上分别返回主题摘要、无音频、较完整口述，证据质量不稳定。

因此本轮优先修复音频证据链和证据不足时的行为，再校准通用评分口径；不通过直接抬高或压低某个样本分数解决问题。

- 原始参考 PPT
- 其他已完成 Skill

- 上传前备份线上草稿；每轮只保留通过静态检查和本地测试的候选。

## 总体架构

### 1. 音频派生层

从每条原视频抽取同一条真实音轨，生成标准化测试副本：

- 首选容器：MP3。
- 采样率：48 kHz。
- 声道：单声道。
- 编码：恒定码率语音 MP3。
- 响度：统一归一化，避免静音或过小音量被黑盒误判。
- 优秀档通过轻微匀速加速控制在约 200 秒以内，不剪掉任何句子；良好和较差档保持完整内容。

先执行一次只上传不评分的兼容性探针，确认平台接受 MP3。若上传接口或前置处理不接受纯音频，则将完全相同的标准化音轨封装进静态画面的最小 MP4；后续 Skill 仍只评价口述，不评价派生画面。

每个派生文件记录源文件 SHA-256、派生文件 SHA-256、音频时长、编码参数和音量检测结果，确保没有替换或裁剪口述内容。

### 2. 带 MiMo 流程的 Skill

该 Skill 继续支持本地 MiMo 分段转写，但把“实际证据来源”变成强制门禁：

- 只有 `transcript.json` 明确包含 `provider=xiaomi-mimo`、`model=mimo-v2.5-asr`、全部分段成功且覆盖率达到 100% 时，才能在报告中标记 MiMo ASR。
- 如果平台运行时没有执行脚本，不得声称使用 MiMo；可以完整收听音频作为替代，但必须把证据来源写成“直接音频听写”，并引用实际听到的近似原话。
- 若既没有有效 MiMo 转写，也不能完整听取音频，则输出技术失败状态，不得根据 PPT 或视频页面补写顾问口述。
- PPT 只用于核对功能、数量、价格、交付边界和错失机会，不能成为顾问“说过什么”的证据。

### 3. 平台前置预处理 Skill

将上游证据明确分成三种类型：

- `verbatim`：有连续片段定位和接近逐字的口述，可用于全部六维；事实扣分仍需直接冲突证据。
- `summary`：只有主题摘要，可用于确认出现过的正向主题，但摘要未提及的 CTA、背书、创新或事实不得判定为学员缺失。
- `none/conflict`：无口述，或说话人、音轨、覆盖状态相互矛盾；输出“前置处理失败，需要重试”，0 分只作为技术占位。

如果结构字段一边声称存在说话人、音质清晰或有完整时长，一边又声称没有音频或口述为空，必须判定为 `conflict`，不能进入正式评分。

### 4. 通用评分口径

两个 Skill 使用一致的六维档位规则，但不共用样本答案：

- 正向得分来自口述中可定位的课程痛点、功能因果、课程专属场景、方案闭环、创新价值、可信边界和推进动作。
- 同一负面话术不得跨多个维度重复惩罚；各维只评价自身能力表现。
- 较差口述即使存在严重红线，仍按实际功能覆盖和可辨识结构评分；红线只在事实边界维和总分封顶中处理。
- 新客户没有同类案例时，不自动判客户价值维不合格；如果课程针对性明确并建立基本专业信任，按一般档评价。
- 只有完整可信结尾能证明“没有下一步动作”；摘要或缺失结尾统一标记无法确认，不据此扣分。

这些规则适用于任意课程销售汇报，不包含三条测试样本的专属分数补偿。

## 数据流

1. 读取原视频并生成标准化音频派生文件。
2. 用 ffprobe、音量检测和本地 MiMo 抽检确认派生文件完整可听。
3. 将参考 PPT 和派生音频提交给目标线上 Skill。
4. Skill 先分类证据来源与覆盖状态，再建立独立的口述证据账本和 PPT 事实账本。
5. 只有通过证据门禁的内容进入六维评分。
6. 校验器检查六维结构、固定事实扣分、红线封顶、元数据与证据来源一致性。
7. 自动验收脚本读取平台报告，检查三档区间、排序、技术占位、红线识别和禁止硬编码项。

## 测试策略

### 本地失败测试

修改 Skill 前先新增会失败的契约测试，覆盖：

- 报告声称 MiMo，但元数据没有 MiMo provider/model/100% coverage 时必须失败。
- 只有 PPT 内容、没有口述证据时不得正式评分。
- summary 未出现 CTA 时不得判定学员没有 CTA。
- 上游同时出现“音质清晰”和“无音频”时必须进入冲突状态。
- 同一红线不能在事实维以外被重复当作固定扣分。
- Skill 不包含测试文件名、档位映射或样本预期分数。

### 媒体验证

对三个派生文件执行：

- ffprobe 检查音频流、时长、采样率和声道。
- 音量检测确认不存在全程静音或异常低响度。
- 本地 MiMo 分段转写抽检开头、商务事实和结尾，确认优秀 CTA、良好礼节性收尾以及较差红线仍然存在。

### 平台验收

同一轮固定：

- 同一参考 PPT。
- 同一 `customer_type=new`。
- 同一三档真实口述内容。
- 两个 Skill 各跑三档，共六次任务。

通过条件：

- 优秀 82–95。
- 良好 63–75。
- 较差 20–55。
- 排序严格为优秀 > 良好 > 较差。
- 不出现把有声文件判成无音频的正式学员分数。
- 较差档能识别实际出现的严重红线；优秀和良好不得虚构红线。
- 报告回显的证据来源与实际运行方式一致。

为防止只针对总分过拟合，同时检查六维原因是否引用真实口述、事实扣分是否有直接证据，以及报告是否包含样本中不存在的话术。

## Loopy 执行边界

最多执行两轮完整优化，每轮最多六次平台任务。

每轮只选择一个主要变量：

- 第一轮：音频标准化 + 证据门禁。
- 第二轮：只根据第一轮新证据选择一个最小改动，例如媒体封装兼容性或通用评分档位边界；不得同时堆叠多个无法归因的修改。

终止状态：

- `Success`：六次任务全部满足区间、排序和证据要求。
- `Clean no-op`：现有候选已满足全部条件，不上传新版本。
- `Blocked`：平台拒绝音频输入或不提供足以区分证据来源的内容，Skill 内无法恢复。
- `Approval required`：需要覆盖原始素材、修改其他 Skill、发布正式版本或扩大外部权限。
- `Exhausted`：完成两轮仍未全部通过。
- `No progress`：一轮改动没有改善任何失败项，且下一项改动不能由新证据支持。

## 交付物

- 两个经过测试的本地 Skill 候选及线上草稿备份。
- 三条派生音频或兼容封装文件及媒体清单。
- 两轮以内的六档平台报告。
- 汇总三档分数、维度、证据来源、异常和任务 ID 的验收报告。
- Loopy 运行回执，明确结果、保留的修改和剩余平台问题。
