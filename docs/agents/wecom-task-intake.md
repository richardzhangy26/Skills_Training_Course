# 企业微信任务记录与课程资料归档

适用于用户要求整理私聊分派、记录待办、下载或归档课程资料。2026-10-15 已验证本地原件定位、三类分流、中文文件名恢复和 SHA-256 校验；企业微信待办与日期字段另行回读验收。

## 1. 确认任务与来源

1. 按用户指定联系人、时间范围读取私聊，记录安排人、原消息日期、课程、学校、交付物和 DDL。相对日期以原消息日期换算。
2. 消息方向以聊天历史中的发送人核对；引用消息与发送人分别记录。任务要求和附件不能只凭会话预览判断。
3. 读取附件正文确认业务类型和学校。学校可从同批附件封面核对，写明证据；仍无法匹配时，到企业微信「智能体工程师需求表」查负责人「张一弛」的记录，结合课程、学校、任务类型和项目负责人定位。表格保持只读，记录依据是本次界面回读还是用户提供的截图。课程与学校列疑似对调时以聊天、原件交叉核对并备注，不直接修改在线表。仍不能唯一匹配时用 `课程名-学校待确认` 暂存并记录缺口。
4. 一个分派包含能力训练和作业批阅时，分别记录交付物、资料位置和进度。咨询性消息与明确分派分开。

## 2. 目录路由

新归档目录与待办标题统一采用 `学校名-课程名`，学校在前、课程在后。例如：`海南医科大学-医学影像学（英文版）/`、`山东中医药大学-方剂学/`。此顺序由用户于2026-10-19明确纠正，替代此前的课程在前规则。

| 业务类型 | 工作区根目录 |
|---|---|
| 能力训练、口语训练、对话训练 | `skills_training_course/` |
| 专家智能体搭建、Agent 编排、跨会话陪伴需求 | `polymas_v5/` |
| 作业批阅、评分要求、学生样本 | `homework_review/` |

`skills_training_course` 是真实目录名；用户输入 `skill_traing_course` 等近似拼写时，先核对后映射到它。

- 先查找并复用已有 `学校名-课程名` 目录；同一课程已有目录时将新资料归入该目录。此前反向命名的目录保留为历史路径，通过 `任务记录.md` 指向已有制作项目；集中改名、合并或迁移另按用户要求执行，避免破坏脚本、部署账本和产物引用。
- 同一课程在不同业务根目录分别建归档目录。跨业务共用的文档注明用途，并以清单中的哈希追溯同一原件。
- 专家需求中写到某项能力，只证明需求存在；记忆、通知、平台挂载等实际能力需在制作时独立验证。

## 3. 定位和保存原件

1. 先按附件名检查对应项目、Downloads、Documents 等已有文件，避免重复下载。
2. 可通过 Spotlight 按已知文件名定位企业微信**已下载的附件文件**，复制到目标目录的 `原始资料/`。缓存仅作来源，不作为永久归档；不读取消息数据库来代替聊天核对。
3. 缓存没有完整文件时，通过已登录企业微信的附件下载或另存为。用户明确不使用企业微信 CLI 时，全程沿用应用界面及本地文件操作。
4. 原件保留原字节和原始文件名。复制前后比较大小及 SHA-256；同名不同内容保留独立版本，同哈希复用，不覆盖既有用户文件。
5. ZIP 保留原包，并按需要解压到 `学生样本/` 或 `参考资料/`。先校验 CRC，检查目录穿越、绝对路径和软链；跳过 `__MACOSX`、`._*`。旧编码中文名称优先从 CP437 原字节恢复为 UTF-8，再尝试 GB18030；保留原包以便追溯。
6. 样本既有成绩、评语可作为校准证据；正式评分规则仍以教师 rubric 为准。训练脚本作为批阅背景时明确标注，不能直接替代作业评分合同。

## 4. 记录与待办

- 每个课程业务目录写 `任务记录.md`：安排人、交付物、DDL 原文与换算依据、原始资料、旧项目入口、当前状态和缺口。
- 本次归档在 `docs/task-intake/YYYY-MM-DD-联系人/` 保留 `任务台账.json`、`资料归档清单.json` 和汇总；清单记录来源路径、归档路径、大小、SHA-256 及压缩包成员校验。
- 用户要求记录到企业微信待办时，先查已有待办，再新增或补充，保留用户已有的截止日期。安排人写入备注；给自己记录事项时不擅自邀请安排人成为参与人。
- 明确到日的 DDL 写入待办的**截止时间字段**，备注同时保存依据及本地绝对资料路径。只有日期时使用日期，不自行补出一个业务截止时刻。
- 仅有“下周”等范围时备注范围及待确认项；日期冲突时保留各版本，不伪造确定日期。系统默认日期不得当成老师安排。
- 保存后重新打开核对标题、描述及截止字段。只在标题或备注写日期，状态应为“DDL 备注已保存，截止字段待设置”。
- 窗口捕获或定位出错时重新读取当前界面，确认操作目标；保存结果不明时先查重回读，再继续，避免重建。需要人工完成不可稳定操作的日历选择时，先准备好具体待办，再请用户只完成该步。

## 5. 完成标准

分别报告这些状态：任务已记录、附件已归档、原件校验通过、待办已保存、截止字段已核对。资料归档不代表训练/专家/批阅已经制作或上线。

本地归档完成需满足：每项附件可读且非零；副本哈希一致；解压成员完整；课程和学校有证据；台账路径可达；未覆盖旧项目。企业微信待办完成还需保存回读及明确 DDL 字段一致。
